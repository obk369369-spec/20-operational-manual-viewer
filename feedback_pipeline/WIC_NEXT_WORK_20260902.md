## 2. 증분 검증 원칙
- 도구 전체 전수검증이 아니라 그날 수정한 범위만 세밀하게 검증한다.
- 각 변경 기능마다 Work가 독립적으로 기대값을 계산/정의한 뒤 실제 결과와 값·행·상태·UI 수준으로 대조한다.
- 불일치 시 FAIL → 수정 → 동일 입력 재검증.
- 직접 영향받는 기존 기능만 회귀테스트하고, 무관한 기존 PASS/REMOTE_VERIFIED는 SKIP_REUSE한다.
- 사용자가 스크린샷으로 모든 기능을 재검증하게 하지 않는다.

## 3. 검증 이력 세부 기록 — 중복 검증 방지 핵심
각 작업마다 최소 다음 필드를 영구 기록한다.
- TOOL 번호/이름
- 작업일시
- 수정한 기능/버튼/옵션/입력범위
- 테스트 위치(소스/로컬 사용폴더/배포본/화면 위치)
- 테스트 입력
- 독립 계산한 기대값
- 실제 결과
- 기대값↔실제값 대조 결과
- 함께 회귀테스트한 영향 기능
- PASS/FAIL/HOLD
- 실패 원인과 재검증 입력
- GitHub commit SHA / remote read-back
- 실제 사용자 폴더 배포 위치
- 배포본 재검증 결과
- 다음 작업에서 SKIP_REUSE 가능한 정확한 범위

검증 기록이 없는 기능은 단순 PASS 라벨만으로 재사용 완료로 간주하지 않는다.
