# TOOL018 MASTER — 18번 도구 기능·정책 정리

상태: ACTIVE / CENTRAL POLICY MASTER / NO SEPARATE REPO REQUIRED
기준일: 2026-08-30
저장 위치: WIC CENTRAL `feedback_pipeline/`

이 대화창은 독립 실행 프로그램이라기보다 **여러 TOOL에서 반복되는 사용자 의도·기능정책·개입 최소화 기준을 추출하는 메타 정책 역할**로 본다. 따라서 별도 저장소를 새로 만들지 않고 CENTRAL에 유지한다.

## 1. 핵심 목적
- 과거 대화기록에서 각 TOOL에 실제로 재사용할 수 있는 사용자 의도와 반복 규칙만 추출한다.
- 현실 구현 상태와 장기 목표/희망을 구분한다.
- 특정 도구에만 해당하는 규칙은 해당 TOOL master로 보내고, 여러 도구에 반복 적용되는 원칙만 공통 운영규칙 후보로 둔다.
- 사용자가 매 도구마다 같은 설명을 반복하지 않도록 한다.

## 2. 현실과 목표 분리
- 대화에서 `언젠가 자동화`, `향후 연결`, `가능하면`, `목표는` 같은 장기 방향을 현재 구현 완료로 해석하지 않는다.
- 실제 화면·파일·실행·로그·commit·read-back처럼 관측 가능한 증거와 목표문장을 분리한다.
- 현실/목표가 충돌하거나 불명확하면 자동으로 숨은 연결·추론을 만들지 않는다.
- 실제 화면에서 보이지 않거나 검증되지 않은 연결을 완료 기능처럼 표시하지 않는다.

## 3. 사용자 개입 최소화
- 정상적인 도구 사용은 사용자가 긴 지시문·반복 설명·반복 테스트를 하지 않아도 되도록 설계한다.
- 과거 여러 TOOL에서 반복적으로 나온 사용자 수정 패턴을 재사용 가능한 규칙으로 정리해 새 TOOL의 초기 설계 품질을 높인다.
- 단, 아직 검증되지 않은 `사용자 의도 자동 예측 100%`를 존재하는 기능처럼 주장하지 않는다.
- 사용자의 개입 감소는 실제 재사용 가능한 master/checkpoint/component가 늘어나는 만큼 증거 기반으로 달성한다.

## 4. 대화기록 사용 원칙
- 사용자가 제공한 기록은 TOOL 번호/역할별로 분류한다.
- 동일 범위 충돌은 더 최신의 명시적 사용자 지시를 우선한다.
- 잡담·일회성 상태질문·과거 가상 진행률은 영구 정책에 넣지 않는다.
- 과거 기록의 특정 단계/파일명이 현재 canonical과 충돌하면 현재 canonical을 우선한다.
- 기록이 부족하다는 이유로 사용자가 어떤 파일을 더 찾아야 하는지 떠넘기지 않는다. 현재 접근 가능한 자료로 먼저 좁게 복구하고, 정말 필수 근거가 없을 때만 SOURCE_EVIDENCE_HOLD로 남긴다.

## 5. 화면/실동작 기준
- 사용자에게 보여주는 TOOL은 실제 화면에서 동작하는 기능을 기준으로 평가한다.
- 보이지 않는 내부 연결, 가상 진행률, `계속 작업 중`, `100% 정렬됨` 같은 표현은 실제 실행 증거가 없으면 상태로 인정하지 않는다.
- 기능의 방향이 맞다는 것과 실제 결과가 100% 완성됐다는 것을 분리한다.
- 실제 결과가 기대와 다르면 `사용자가 의도를 잘못 전달했다`가 아니라 규칙/실행/검증 어느 층의 문제인지 좁게 판단한다.

## 6. 반복 피드백을 자산으로 전환
- 사용자가 여러 도구에서 반복해 고친 패턴은 다시 설명하게 하지 않고 master 또는 검증된 reusable component 후보로 만든다.
- 첫 사례는 TOOL 로컬 규칙, 반복 사례는 공통 후보, 실제 여러 TOOL에서 재사용 PASS가 확인되면 공통 규칙/컴포넌트로 승격한다.
- 공통화를 위해 전체 WIC를 조사하지 않는다.

## 7. `업데이트` 및 선제 운영제안
- 사용자가 `업데이트`라고 입력하면 해당 대화에서 나온 신규 영구 정책을 대상 master에 DIFF ONLY로 반영하는 명시적 저장명령으로 사용한다.
- 사용자가 알기 어려운 단축명령·기존 기능·Work 불필요 처리방법·자동화 가능성이 발견되면 먼저 설명한다.
- 사용자가 무엇이 가능한지 몰라 질문하지 못했다는 이유로 효율화 기회를 숨기지 않는다.

## 8. 과거 잘못된 상태보고 폐기
- 과거 기록에 있던 `70%`, `남은 12%`, `계속 자동 보정 중`, `방향 100%` 등 실제 백그라운드 실행 없이 보고된 수치는 현재 사실/검증 상태로 재사용하지 않는다.
- 실제로 실행되지 않는 작업을 시간이 지나면 진척되는 것처럼 보고하지 않는다.

## 9. 2026-08-30 catch-up
- 18번 기록의 핵심은 별도 실행도구 개발보다 `사용자 의도·과거피드백을 실제 TOOL 정책으로 재사용하고 사용자 개입을 줄이는 메타 운영`으로 정리한다.
- 별도 repo를 만들 가치가 없는 중앙 정책 역할이므로 CENTRAL에 보존한다.
- 이후 18번 대화에서 `업데이트` 입력 시 신규 영구 정책만 DIFF ONLY 반영한다.
- 실제 GitHub write/commit/read-back 없이 업데이트 완료라고 보고하지 않는다.
