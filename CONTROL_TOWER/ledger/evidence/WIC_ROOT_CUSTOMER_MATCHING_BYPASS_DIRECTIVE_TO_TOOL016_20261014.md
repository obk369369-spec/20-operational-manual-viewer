## 0. 최하위 공통 ROOT (증상 아닌 실행구조 결함)
ROOT: **권위 있는 원본·최신규칙·필수 근거·검증게이트·실행결과가 한 트랜잭션으로 묶이지 않은 상태에서, 대화형 모델의 자유생성 경로가 검증 없이 고객용 산출물을 발행할 수 있는 구조적 BYPASS**.
문서에 규칙을 썼다는 사실은 런타임 실행을 의미하지 않는다. 규칙·근거·입력·출력·증거가 분리된 채 '그럴듯한 텍스트'를 완료로 취급하는 결함이 최하위 공통 원인이다. 다른 도구에서도 동일한 무검증 완료·가짜 PASS·근거 없는 자동반영·사용자 재확인 강요를 일으킨다.

## 1. 연관 오류를 누락 없이 추적할 감사 범위
A 규칙 소스: GitHub canonical vs 대화 기억/요약/Work/에이전트/복제본 충돌, 버전 SHA 미고정, 미조회, 부분조회·truncation, 최신 피드백 누락, 문서 수정과 코드 적용 혼동.
B 고객 신원: 동명이인, 현직·부서·직책·연락처·실제 담당업무 미검증, 기관 업무를 개인 연구로 오인, 오래된 논문을 현재 연구로 단정, 공식출처·발행일 누락.
C 과거 이력: 개인·기관 과거 발송/견적/구매/문의/회신 및 Thunderbird EML·ZIP·고객장부·GitHub 인덱스 간 불일치, 동일 제목/발행사/개정판/유사 주제 중복, 고객별 수신자 오인.
D 안내서 소스: WIC 내부 실제 DOC/DOCX 원본 파일 존재 미검증, 대화 메모·파일명 추정·외부 후보를 내부 확정으로 오인, 출처·파일경로·버전·해시 미보존, 무차별 전체 재스캔.
E 보고서 메타: 공식 원발행사 제목 축약, 발행사/페이지/발행일/가격/라이선스/환율/공급가 혼동, 중개사이트 대체, URL 오염, 목차 아닌 메뉴를 TOC로 오인, TOC 잘림, 3종 발행사/주제 중복.
F 매칭: 최신 개인 연구와 보고서 실제 목차의 근거별 교차표 부재, 키워드 유사성만으로 적합성 단정, 상이한 연구축을 뭉뚱그림, 추정/후보/PASS 미분리, 누락 항목을 생성으로 메움.
G 고객 산출: 실제 발송 EML 골든샘플 미조회, 제목/인사/설명/문의문구/회사 고정서명 불일치, 수신자 혼동, 과도한 보고서 나열, 본문·첨부자료 연결 실패, 링크/서식/복붙 흔적.
H 실행·운영: 코드/워크플로/배포/실사용 테스트 없이 '업데이트/전달/완료' 선언, 도구 간 전달 불능, 권한·커넥터·환경 장애, 부분 실패 후 계속 생성, 관찰자에게 자료 재전송·수동 복붙 전가, 미완료 큐 소실, 로그와 실제 증거 불일치.
I 전파: 1·7·13·16·42·44번 및 공통 메일/조사/자료매칭/목차/발송/배포 경로에 동일한 실패 패턴이 있는지 의존성 그래프 기반 역방향·정방향 추적. 특정 고객·도구만 패치 금지. 발견된 미지의 연관 오류도 등록.

## 2. 강제 실행 파이프라인
(1) 기존 canonical 체크포인트·PASS evidence·Registry·Backlog·Queue 재사용, 최신 규칙 SHA 및 원본 EML/고객장부/실제 안내서 파일 식별.
(2) 고객별 개인 현직·연구를 최신 공식 근거와 대조. 불명확하면 UNKNOWN/HOLD, 기관 일반정보로 대체 금지.
(3) 고객 개인 및 기관 발송이력·동일/개정판/유사 중복 교차검증. 확인하지 못한 원본은 MISSING SOURCE로 기록.
(4) 내부 실재 안내서 3종을 공식 발행사 메타·전체 TOC와 대조. 직접 연구축별 매칭 근거, 상호 중복성, 과거 발송 여부를 기록. 외부 후보는 별도 표시.
(5) 모든 필수 항목 PASS인 경우에만 최종 추천·메일 작성. 실제 발송 EML을 GOLDEN SAMPLE로 삼고 제목/본문/3종 설명/고정서명 전체 비교. 사용자 지시대로 메일은 한 번에 복사 가능해야 함.
(6) 필수 근거 미확인 시 FAIL-CLOSED: 추정 결과를 발송가능으로 표시하지 않고 누락 근거/차단 사유만 보고. 사용자에게 기존 자료 재업로드/수동 테스트 요구 금지.
(7) 독립 실행기/외부 검증구조에서 코드·테스트·증거를 실행하고 결과를 원격 read-back. ChatGPT/Work/Codex 안에서 개선만 반복하는 폐쇄 루프 금지. Codex는 검증된 외부 실행구조에 연결된 개발엔진 부품으로 사용. 검증된 즉시 꽂아 쓰는 조합 우선, 새로운 장기간 접착·통합공사 금지.

## 3. 재발방지 테스트 / 수용조건
- 반례: 오래된 연구만 존재, 동명이인, 기관 연구만 존재, 원본 DOC 부재, 3종 중 1종 TOC 누락, 같은 발행사/유사 주제, 이미 발송한 개정판, EML 본문과 서명 누락, GitHub 규칙 수정 뒤 런타임 미적용, 도구·환경 장애, 미확인 링크/가격, 인덱스 불완전.
- 모든 반례는 산출물 최종확정 차단 및 OPEN/HOLD 증거 등록. 정상 사례는 실제 발송 EML 골든샘플과 고정서명·수신자·자료의 회귀테스트 통과.

- 코드 PASS ≠ DEPLOYED COMPLETE. 독립 실제 테스트·배포 스모크·사용자 화면 접근 확인 전 완료 선언 금지. 재발 0건 목표는 실제 관측 기간과 표본으로만 판정.
