## 사용자 지시 및 실패
사용자는 기존 최상위 구조, 원본, 지시, 규칙, PASS_LOCK, Evidence, Registry, Queue, Backlog, 내부 안내서와 실제 이력을 먼저 사용하여 끝까지 결과물을 만들라고 반복 지시했다. 그런데 보조 모델이 구조의 실제 실행·원본 전체 확인 없이 부분 파일 검색과 자체 추론으로 추천과 이메일을 작성했다. 내부 전체 검색을 하지 않았음에도 최종 선정처럼 표현했고, 확인되지 않은 직함·공급 가능성·중복 검증을 남겼다. 이는 단순 누락이 아니라 중앙 규칙 적용 실패 및 실행 증거 부재다.

2. 중앙 규칙이 대화창/Work/각 도구의 요청에 실제 주입되고 실행되는지 코드와 로그로 확인한다. 규칙 문서의 존재만으로 적용 완료 선언 금지.
3. 요청마다 기존 확정 지시·필수조건·원본 식별자·중복/권한/출력 요건을 작업 명세로 복원한다. 접근하지 못한 원본을 읽었다고 주장하거나 빈칸을 추론으로 메우지 않는다.
4. 소스 우선순위·전체 검색 범위·중복 확인·실제 결과물·검증 기준을 실행 게이트로 강제한다. 내부 원본 전체 검색을 요구한 작업에서 부분 검색만 했으면 COMPLETE/PASS 금지. 검증 가능한 증분 인덱스가 있다면 이를 재사용한다.
5. 자료 검색/매칭/조사/문서/이메일/엑셀/배포/자동화 등 전 유형에 공통 적용. 특히 고객 업무에서는 현직·직함·부서·업무·실제 연구 분야의 출처와 날짜, 개인/기관 전체 과거 이력, 내부 안내서 우선, 부족 시 외부 후보, 실재 보고서/목차/연도/가격/페이지/중복 검증, 받는 사람·제목·본문·고정 서명까지 일괄 산출한다.
6. 추론/가정/후보/검증완료를 명확히 분리하고, 핵심 근거가 부족하면 FAIL-CLOSED. 근거 없이 최종 선정·발송 가능·구현 완료·정상 배포·자동 전달을 선언하지 않는다.
7. 원인 전파 분석: 규칙 불러오기, 원본 접근, 도구 호출, 모델 판단, 상태 동기화, 증거 저장, 최종 출력, 자동복구 등 관련 전 구조를 제한 없이 점검. 동일 결함이 다른 도구에도 있으면 공통 게이트에서 교정한다.
8. 기존 플랫폼을 소켓형으로 재사용하고, 불필요한 신규 구축·연결 작업·수동 복붙·원본 재제출·사용자 테스트 요구 금지. 실제 불가한 자동 전달은 완료로 주장하지 말고 차단 지점과 실행 가능한 연결 경로를 기록한다.
9. 실제 코드/워크플로 변경 → 서로 다른 작업 유형에서 성공/실패/차단/복구 테스트 → 사용자 화면 최종 산출물 확인 → 증거와 commit을 남긴다. 사용자에게 설명문만 출력하는 것으로 종료하지 않는다.
10. 이미 검증된 결과는 재사용하고 실패한 최소 범위만 증분 복구. 실행 환경이 차단되면 체크포인트 보존, BLOCKED 명시, 허위 PASS 금지.
