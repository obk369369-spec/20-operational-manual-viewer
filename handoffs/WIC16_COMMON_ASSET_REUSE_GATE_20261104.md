## 신규 설치·다운로드·재작성 전 필수 순서
1. 중앙 GitHub의 기존 인계·증거·경로·버전·프로젝트 ID·실행 기록을 먼저 검색한다.
2. 기록된 경로와 실제 파일 존재를 분리하여 확인한다. 경로가 없으면 기존 디스크의 다른 설치 위치·백업·프로젝트 폴더를 먼저 찾는다.
3. 기존 실행 파일이 사라졌어도 원본 프로젝트는 별도로 보존하고, 실행 환경만 복구한다.
4. 기존 자산을 사용할 수 없다는 구체적 증거를 남긴 뒤에만 공식 무료 배포본 재다운로드를 허용한다. 임시 폴더에만 설치하지 않고 지속 경로를 우선한다.
5. 다운로드·압축 해제·프로세스 시작은 업무 완료가 아니다. 실제 프로젝트 조회, 입력·출력 검증, 업무 Job/ACK를 각각 별도 기록한다.
6. 독립 작업의 장애는 격리하고 다른 작업은 진행한다. 검증된 공통 원인만 ROOT로 통합한다.

## 중복 실행 차단 강화 (2026-11-04)
- OpenRefine 3.10.0 배포본 확보와 기존 프로젝트 API 연결이 확인되었으므로 동일 배포본 다운로드, 압축 해제, 신규 GVR 프로젝트 생성은 SKIP_LOCK 대상으로 취급한다.
- 사용자에게 거부된 신규 GVR 프로젝트 생성은 REJECTED_LOCK. 다른 명령으로 우회 재시도하지 않는다.

- 검사·다운로드·문서 커밋은 신규 업무 Job 또는 해결 ROOT로 계산하지 않는다.
