## 범위 및 원칙
42번 고객 안내에 한정하지 않고, 16번 플랫폼으로 이전하는 전체 업무·프로그램·도구·자동화·데이터 구조에 적용한다. 1·2·12·13·16·42·49·51·52·53번 및 중앙 관리 구조를 포함하며, Registry에서 발견되는 관련 작업도 포함한다. 기존 HOLD 및 승인 범위는 유지한다.
중앙 저장소: obk369369-spec/20-operational-manual-viewer. 기존 Registry, Handoff, Checkpoint, Evidence, Queue, PASS_LOCK, 브랜치 및 실제 실행 상태를 우선 확인한다. 원본 삭제·무단 덮어쓰기·중복 자체 개발을 금지한다.

## 최하위 공통 원인 및 연쇄 오류
1. 과거 대화·첨부·메일·파일·프로그램에 접근하거나 재발견하지 못하는 기록 접근 오류
2. 입력·고객 원장·업무 규칙·출력물 간 식별자 및 경로 불일치
3. 실제 업무 상태와 중앙 원장·GitHub·후속 작업의 동기화 실패
4. 대화에만 남고 영구 저장소에 반영되지 않는 저장 누락
5. 커밋·로그만 확인하고 실제 입출력 및 재조회 검증을 하지 않는 오류
6. PC 종료·세션 만료·인증·경로 변경에 따른 외부 실행 중단
7. 대화창·Work·Codex 전환 시 특이 사항과 재개 지점이 누락되는 인계 오류
8. 기존 결과를 찾지 못해 조사·개발을 반복하는 오류
9. 외부 완성형 도구를 조사만 하고 실제 연결·작동시키지 못하는 오류
10. 무료 운영·권한·개인정보·보안 조건 미충족

오류별로 ROOT_CAUSE, 연결 오류, 영향받는 작업 ID, 기존 자산, 해결 방법, 실제 검증 증거, 재발 여부를 연결해 관리한다. 개별 증상별 패치를 반복하지 말고 공통 원인을 수정하고 영향 작업 전체에서 회귀시험한다.

## 공통 데이터·실행 흐름
원본 자료 → 추출 → 표준화 → 중앙 원장 → 업무 처리 → 결과물 생성 → 실제 검증 → 영구 저장 → 다음 작업 인계.
각 단계는 고유 ID, 출처, 버전, 상태, 검증 시각, 결과물 경로, 오류·복구 정보를 보존한다. GitHub는 저장·추적 계층이지 24시간 실행 서버가 아니다. 외부 완성품 및 기존 설정을 우선 재사용하고 무료 외부 실행 환경을 실제 검증한다.

## 병렬 처리 그룹
A 기록·첨부·데이터 누락; B GitHub·중앙 원장·상태 불일치; C 외부 완성형 도구 연결·재사용; D 인증·실행 환경·24시간 지속성; E 출력물·실제 업무·복구 시험. 독립 작업은 병렬, 동일 파일 동시 수정 및 원본 충돌은 직렬 통제한다.

## 누적 저장 및 복구
모든 실제 변경마다 작업 ID, 마지막 성공 단계, 수정 파일, 원본·출력물 경로, 고객·업무 특이 사항, 완료·HOLD·FAIL 사유, 다음 실행 조건, 커밋·검증 증거를 기록한다. 대화 요약만으로 완료 처리하지 않는다. 중단 후 저장된 실제 데이터·실행 상태를 재조회해 이어서 진행해야 한다.
공개 저장소에 고객 이메일 원문, 개인정보, 계약·승인 비공개 자료를 올리지 않는다. 비공개 저장이 불가능하면 민감정보는 저장하지 않고 HOLD한다.

## PASS 조건
실제 입력 성공, 기존 규칙 재사용, 업무 출력물 생성, 원본과 결과 대조, 영구 저장 및 재조회, 중단 후 재개, 중복 실행 무손상, 관련 작업 회귀시험, 무료·권한·보안 준수를 모두 확인한다. 미검증은 PARTIAL/HOLD/BLOCKED/FAIL로 기록한다. 커밋·계획·목업만으로 PASS 금지.
