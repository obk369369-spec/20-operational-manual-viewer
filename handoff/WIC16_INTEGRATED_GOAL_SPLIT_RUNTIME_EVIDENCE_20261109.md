'24시간'은 서버 하나가 상시 켜져 있다는 주장과 다르다. 정해진 업무가 자동 재개·상태 보존·실패 복구되고, 실제 24시간의 실행 로그 및 산출물로 증명되어야 한다.

## 확정 원칙
1. GitHub 저장소의 기존 자산만 재사용. 대화창·USB·기타 도구에서 기존 자산을 다시 찾거나 연결하려고 반복하지 않는다.
2. 단일 무료 호스트 부재를 전체 STOP 사유로 삼지 않는다. 기능별 분산 실행 및 독립 lane을 우선한다.
3. 내부 스크립트/프로그램/API 연결 신규 개발, 중복 구축, 유료 플랫폼, Work/Codex 크레딧 소비 금지.
4. 승인·STOP·원본 검증 게이트 우회 금지. 승인 없는 컨트롤러는 HOLD, 안전한 독립 lane은 분리 판단한다.
5. 문서 커밋/감사 PASS를 운영 성공으로 표시하지 않는다. 실물 입력→처리→출력과 24시간 경과 증거가 필요하다.
6. 실패 원인이 이미 확정된 Oracle 재가입 및 Kestra 재설치/재시험을 반복하지 않는다. 사용자 수작업과 재승인 요구 최소화.
